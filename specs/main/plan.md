# Implementation Plan: RealmsDraft ↔ Summit API Integration

**Branch**: `main` | **Date**: 2026-04-02 | **Spec**: [spec.md](specs/main/spec.md)
**Input**: Feature specification from `specs/main/spec.md` + user requirements for RealmsDraft API

## Summary

Add REST API endpoints to the Summit web app so that RealmsDraft (an external draft management service) can manage player arena run lifecycle. Three endpoints: GET user status, POST to start/forfeit a run, POST to end a run with ELO penalties. The Discord bot's limited arena system (database tables, ELO tracking, match reporting, forfeit logic) is already fully implemented - this plan covers only the new API surface and queue validation rules.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: Flask (web app), discord.py 2.3+ (bot), SQLite3
**Storage**: SQLite - `match_records.db` (arena runs, match records, pairings), `elo.db` (limited ELO)
**Testing**: pytest (discord-bot/tests/), manual curl testing for API endpoints
**Target Platform**: Linux server (systemd + Nginx + Cloudflare)
**Project Type**: Web service (REST API additions to existing Flask app)
**Performance Goals**: N/A (low volume, server-to-server calls)
**Constraints**: Shared SQLite databases between discord-bot and web-app; no concurrent write contention expected
**Scale/Scope**: 3 new API endpoints, 2 new files, 2 modified files
